# Observations

Items without a documented expected result: risks, UI behaviour and differences between doors. They are not reported as bugs. Bugs with a documented expected result are in [FINDINGS.md](FINDINGS.md).

Levels as in `ARCHITECTURE.md`: **Verified** (proven by response substitution, 3 November), **Observed** (seen, effect not proven), **UNKNOWN**.

| ID | Area | Observation | Level, date | Why it matters |
|---|---|---|---|---|
| O1 | Generator | Shows domains as available with "Get It" after one `suggest-domains` call for the first generated name; no `check-domain-availability` and no bulk check before selection. Its answer rests only on the documented promise that a suggestion is available for purchase. Re-check at selection: UNKNOWN. | Observed, 3 Nov | If a suggestion is wrong, the user learns at checkout. Mitigation: `public-api.spec.ts` and `generator.spec.ts` check the first suggestion with `check-domain-availability`; both passed in the full run at 15:47. A sample, not proof. |
| O2 | API errors | Validation errors without a documented format: `paging.limit=abc` returns 400 "Failed to parse JSON or deserialize protobuf message" with `details: {}` and no field; `paging.limit=0` and `paging.limit=100` return a sentence plus `violatedRule` (`MIN`, `MAX`). | Observed, 3 Nov | Clients that branch on documented codes cannot handle them; the parse error names no field and exposes implementation detail. |
| O3 | API docs | Auth: the text says the call cannot use the standard authorization header, yet the curl examples send only `Authorization: <AUTH>` and the SDK examples pass a `siteId`; `wix-account-id` is not mentioned. Deprecated `limit` is still listed with "will be removed on March 1, 2025". | Documented, read 3 Nov | Together with F1, an integrator cannot learn which headers are required. |
| O4 | UI: Storefront, WHOIS, Generator | The first search submitted right after the page's `load` event is ignored: on the Storefront and WHOIS in every try in Playwright on 3 Nov, on the Generator once. A second submit works. | Observed in automation, 3 Nov | A fast user may click and see nothing. Impact on real users UNKNOWN: people type slower than a script. Web tests retry the search until the page navigates. |
| O5 | UI: Generator | Console error about `borderColor=""`, and the error border drawn as `rgba(255,0,0,0)`, a fully transparent red. Possibly an error state the user cannot see. | Observed 2–3 Nov; not re-checked | If confirmed, invalid input gives no visible signal. Needs a visual check. |
| O6 | Web vs public API | Web doors send the suggest query with a TLD (`query=google.com` on the Storefront, `query=Agenticqa.com` on the logged-in dashboard), although the public contract says no TLD; they also use a bulk availability call and no key. | Observed, 3 Nov | Internal endpoints, not the public contract; but the two paths validate input differently. |
| O7 | Suggest paging | `pagingMetadata.cursors.next` is unsigned base64 JSON holding the query, the suggestions shown and a pending list marked `engine: "Llm"`. | Observed, 3 Nov | The client carries the next page itself; tampering not tested (Deferred, security). |
| O8 | WHOIS | Details arrive after about 15 seconds (a 9-second wait gave a false negative). The banner reads "is taken" or "is registered" in different sessions. The entry page, not the result page, decides the branch. | Observed, 2–3 Nov | Slow answer to the core question; wording cannot be asserted. |
| O9 | Web call sets | Input without a TLD produced different call sets between loads; `paging.limit` was 10 in some sessions and 50 in others; the result URL appears with and without a slash after `result`. | Observed, 2–3 Nov | Tests assert what the screen means, not which calls happen or the exact URL. |
| O10 | Logged-in and edge endpoints | `structured-domain-info/whois` returned 403 when logged in (200 anonymous); `domainTransferInValidation` returned 200 with `status: -987` and `&#039;` in the message; `domain-broker-offers/query` returned 500 "Failed to extract tenant" anonymously. | Observed, 2–3 Nov; not re-checked | Screen effects UNKNOWN; logged-in flows are outside the anonymous test conditions. |
